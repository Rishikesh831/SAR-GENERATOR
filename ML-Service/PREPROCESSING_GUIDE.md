# Layer 1.5: Data Normalization & Preprocessing 🛠️

In AML system architectures, the quality of intelligence generated by the Machine Learning (Layer 2) and Graph Engines (Layer 3) is completely dependent on the integrity of the inbound ledger data. 

Because we cannot guarantee that an external database or analyst CSV file perfectly conforms to the internal topological formats our pipeline expects, we employ a dynamic normalization and feature extraction pipeline (`data_preprocessor.py`).

---

## 1. Automated Irrelevant Row Deletion
The first step before any arithmetic or AI model evaluation occurs is stripping corrupt, noisy, or AML-irrelevant rows. Analyzing useless nodes exponentially degrades Graph throughput and produces dirty XGBoost anomalies. 

The `filter_irrelevant_rows(df)` method automatically aggressively prunes:

*   **Identical Self-Transfers (`sender_account` == `receiver_account`)**: In real-world banking ledgers, identical sender/receiver pairs usually signify internal wallet transfers or monthly account maintenance fees. Because they do not establish graph edges (cycles), they are safely deleted.
*   **Missing Critical Identities**: Rows missing a `sender_account` or `receiver_account` are immediately pruned. Network mathematics (NetworkX) explicitly requires a Source and Target node.
*   **Zero/Negative Values (`amount` <= 0.0)**: Reversed transactions, failed wire-bounces, and zero-balance "pings" are pruned structure-wise as they do not constitute active layerable cashflow.

---

## 2. Dynamic Feature Engineering
Once the data is filtered, the ML Engine requires specialized behavioral columns. If the inbound data does not explicitly provide them, the Preprocessor synthesizes them dynamically from the core transactional columns.

### A. Frequency Synthesis (`n_daily_txns`)
*   **Why it's needed:** XGBoost uses this to identify structuring behavior.
*   **How it handles missing data:** The script uses Pandas to `groupby(["sender_account", "Date"])`. It counts exactly how many times the sender executes a transaction on that specific date, effectively turning a static transaction list into a behavior timeline.

### B. Geopolitical Mapping (`high_risk_country`)
*   **Why it's needed:** Required by Layer 2 to compute intersection probability with the FinCEN Prior Vector.
*   **How it handles missing data:** The script relies on the generic `country` string. If `country` == "NG", the preprocessor intersects it against a predefined `HIGH_RISK_JURISDICTIONS` dictionary. It forces the output into a strict `1` or `0` binary integer expected by the ML matrix.

### C. Regulatory Boundaries (`below_ctr_threshold`)
*   **Why it's needed:** Marks the mathematical blueprint of Smurfing (sending $9,900 to evade $10,000 regulatory reviews).
*   **How it handles missing data:** Computes this mathematically by assessing: `if amount >= $8500 and amount < $10000: flag=1`.

### D. Velocity Spikes (`velocity_spike`)
*   **Why it's needed:** Identifies account-takeover or sudden shell company activation.
*   **How it handles missing data:** Converts the synthesized `n_daily_txns` into a boolean signal threshold (defaulting to `>= 5` transactions per day).

## Summary
To execute this normalization, simply pass your unrefined pandas dataframe into `TransactionPreprocessor.process(df)` prior to passing the dataset into the XGBoost evaluation functions or the GraphBuilder class.
